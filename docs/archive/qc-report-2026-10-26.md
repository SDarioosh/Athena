# QC report of 2026-10-26 (written notes, PR #108): verification and fixes

The QC bug hunt against PR #108 ("written notes from the hub", `POST /v1/ingest/text`)
listed 8 bugs on the Athena side (A-1 to A-8) and one mismatch with the hub's handwriting
stage (X-1). Each claim was checked against the code at `0ea659f`. A bug counts as
reproduced when a regression test failed on the old code. All tests are in
`server/tests/test_qc_written_notes.py` (34 tests; 20 failed on the old code, the other
14 guard behaviour that must not change or show that a claim does not hold).

**Result: 7 claims were real and are fixed (A-3 and X-1 partly: the rest is intended
behaviour), 2 did not reproduce.** Where a fix differs from the proposed one, the reason
is given below.

Verdicts: **C** confirmed, **P** partly confirmed (the row says which part), **N** not
reproduced, **D** real behaviour, a design decision for the owner.

## Limits for the hub (`POST /v1/ingest/text`)

| What | Athena's answer |
|---|---|
| `text` over 200,000 characters | 422 |
| `text` with no words (empty, only spaces) | 400 "text has no words": send `DELETE /v1/ingest/text/{source_id}` instead |
| more than 5,000 non-empty lines (after wrapping) | 400 |
| a line over 4,000 characters | accepted, wrapped at a space |
| `link` over 2,000 characters | 422; with a space, quote, `( ) < > { } \| \ ^` `` ` `` or user info, 400 |
| `title` over 200 characters | 422 |

## Behaviour changes

- A note line that says an erased fact of *any* conversation is stored `[forgotten]`
  (it was only the note's own erased facts), and the match is stricter (every word of a
  short fact). Lines matched that way are not fingerprinted any more.
- A resend moves the note's facts' and to-dos' line offsets with their lines.
- Deleting a note keeps its erased facts' sentences (`erased_facts`, new table, created on
  start) and keeps what its forgotten facts had replaced replaced.
- Links with the characters above are refused; long lines are wrapped instead of refused.
- No tool name, argument, annotation or JSON field changed: no MCP version bump. The
  text of `list_facts` gains the written-by-hand label on two kinds of lines.

## Open for the owner

- A fact erased in a note that was then deleted, said again in a **recording**, becomes
  a fact again: only written notes are checked against `erased_facts` (the recording's
  repeat is linked "same" only while the erased fact's row exists). Keeping the facts row
  of a deleted note would need a conversation to hang it on.
- A-2's paraphrase case: a resent line that says an erased fact in other words stays
  readable (the re-summary keeps the fact erased). Redacting the line the re-summary cites
  for it would close that, at the risk of a wrong cite.
