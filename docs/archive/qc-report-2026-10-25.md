# QC report of 2026-10-25 (action items and beliefs): verification and fixes

The QC audit listed 15 bugs in the server's action items, facts (beliefs), MCP tools and
date/list parsing. Each claim was checked against the code at `2401ecb`. A bug counts as
reproduced when a regression test failed on the old code. All tests are in
`server/tests/test_qc_action_items_beliefs.py` (40 tests; 30 failed on the old code, the
other 10 guard behaviour that must not change).

**Result: 11 bugs were real and are fixed (two narrower than reported, two a little wider),
1 is real behaviour but outside the documented `erase_fact` contract and is left for the
owner, 3 did not reproduce.** Several severities were overstated. Where a fix differs from
the proposed one, the reason is given below.

Verdicts: **C** confirmed, **P** partly confirmed (the row says which part), **N** not
reproduced, **D** real behaviour, a design decision for the owner.

## Behaviour changes

- `list_action_items(person=X)` returns more: items X owns, names X, or come from a
  conversation with X. With no `person`, results are unchanged.
- `list_action_items(status="")` lists open items (it listed every status).
- `list_facts(query)` and fact linking see more facts in a busy database, so fewer repeats
  become a second belief. The links the model is offered are still capped at 15.
- `erase_fact` may redact a line next to the cited one (see 03), never one more than 30 s
  away, and only one line per conversation, as before.
- No tool name, argument, annotation or link changed: no MCP version bump.

## Open question for the owner

- **12:** should forgetting a fact also take action items with its words out of search and

  the hub keeps its own filed copy, so it needs the hub side too.
