# QC bug report of 2026-10-24: verification and fixes

The QC agent's report listed 45 bugs across the server, both firmwares, the Android and
PC relays and the Zepp app. Each claim was checked against the code at `347c5e0`. A bug
counts as reproduced when a regression test failed on the old code, or, for device-only
code, when the faulty path was traced in the source.

**Result: 40 bugs were real in some form and are fixed (several narrower than reported),
5 did not reproduce.** The report's repro files (`repro_server_1.py` and others) don't
exist; every bug was reproduced from scratch. Many severities were overstated, and some
of the proposed fixes were wrong. Where a fix differs from the proposed one, the reason is
given below.

Verdicts: **C** confirmed, **P** partly confirmed (the row says which part), **N** not
reproduced.

## Noticed, not fixed (outside the report)

- `resolve_due` still reads "one may" as May 1 ("may" is also a verb).
- After a re-summary, an edited note's `note_title` goes back to the model's value
  (`_same_item` doesn't carry it over).
- `LLMClient.structured`: a `content` that isn't a string still raises in `_strip_fences`.
- Recorder: `cq_init` still aborts if recovering an open chunk hits a read error; `cq_end`'s
  failure path skips the card power cycle that `abandon_chunk` does.
- `docs/twatch-ble-protocol.md` §7 ("queued since the last BYE") should now say "offered
  before the last BYE" (R5).
- PDA: `json_quote` would pass broken UTF-8 through (its input is now always valid).
- Android: `GattClient` doesn't close `BlePdaLink.statuses` on disconnect (A2 hardening).
- Zepp: the main page's `ping()`/`uploadAll()` call `render()` after `onDestroy` (like
  Z1); `onDestroy` drops the recorder without calling `stop()`.
- `pull.py` can't fetch card files with spaces in their names.
