  `vision.sock`. Found and fixed: the keyboard's code mode had capitals only, so a pairing
  code (mixed case, `_`) couldn't be typed; `pda_sync` reported a token refused at the
  hub's health route as "not reachable" (now `auth_failed`; the PC relay's `/health` needs

- CI: jobs `firmware-k230-ui` (screenshots as an artifact), `-vision` (+ ASan/UBSan),

  the owner's checklist is in `firmware/pda-k230/README.md`.

## Done on 2026-11-04: action item times are not due dates

- `list_action_items` (text format) ends each line with the time the item was said, with
  no label, and the voice assistant read it as a due time ("Order PETG filament due at
  4:51 PM" for a to-do with no due date). The result's first line now says that time is
  when the item was said and that only an item with "due ..." has a due date; the tool
  description says the same. The lines themselves are unchanged, because the hub parses
  them (`fork/athena/action_items_state.py`, `fork/athena/view.py`). Not a contract change:
  no tool name, argument, annotation, link or JSON field changed.

## Done on 2026-11-03: identify who spoke a command (MCP 0.22.0)

- `POST /v1/speakers/identify` (`server/athena/speaker_identify.py`): multipart `audio` (a
  voice satellite's spoken command) → `{"speaker": {id, name, is_owner} | null, "score",
  "threshold", "speech_seconds"}`. VAD speech, the diarizer's speaker embedder and the
  enrolled voices, scored like diarization's matching; threshold
  `CONVO_SPEAKER_IDENTIFY_THRESHOLD` (unset: `CONVO_SPEAKER_MATCH_THRESHOLD`, 0.50).
  `speaker` is null below it or with less than 1 s of speech. At most 2 MB and 20 s. The
  audio is never stored or logged, nothing is written to the database.
- Relay route `POST /speakers/identify` on the MCP HTTP app (forwarded unchanged), for the
  hub's voice satellite check (`FORK_VOICE_PRIVATE=owner` answers personal questions only
  for the owner's voice). MCP 0.22.0, additive. Contract in `docs/api/ingest.md`.
